## 核对依据与限制

- 商品列表与详情的实际 GET 响应已核对，均未包含 SKU ID、SKU 列表或库存。SKU 接口本身也未声明库存字段。
- 商城当前只有商品列表、商品详情、购物车和收银台四类页面；收银台只保存支付会话 ID，没有订单详情路由或取消订单按钮。
- 此前范围核对仅发起只读 GET 请求；本次注册联调的覆盖范围见下文，未调用下单、支付或取消订单。
- 后端未来补充接口时，需要重新核对最新文档；当前清单不意味着文档以外的服务一定不存在。

## 此前登录接入行为与验证结果

- 登录表单按后端要求使用邮箱和密码，保存用户 ID 与两类 Token；表单包含加载、错误提示、防重复提交及离页响应保护。
- Access Token 过期或鉴权请求返回 401 时，续期并保存轮换后的 Refresh Token；并发请求共享续期，失败不会无限刷新。网络或服务暂时故障保留会话，明确凭据失效才清理会话。
- 页面装配使用真实登录状态，取消原先固定的已登录状态和硬编码权限。未登录访问收银台进入账号密码登录，登录后购物车保留。扫码授权沿用已有 `requiresAuth` 限制，仅登录后可进入。
- 会话仍使用项目原有内存存储；本次未新增重启 App 后的持久登录能力。
- `npm run typecheck`、`npm run lint`、`npm test -- --watch=false` 全部通过：21 个测试套件、192 项测试。
- `npm run bundle:android` 与 `npm run bundle:ios` 均通过；覆盖 JS Bundle 构建，不代表原生安装包或真机验收。
- 本地接口探测确认：登录及刷新参数非法返回 `400 VALIDATION_FAILED`；不存在的测试账号返回 `401 INVALID_CREDENTIALS`；无效签名的测试 Token 返回 `401 REFRESH_TOKEN_INVALID`。未创建账号、订单或支付。
- 尚未提供真实账号，因此成功登录与成功轮换使用模拟 HTTP 响应做集成测试，尚未完成真实账号的成功链路联调；按要求未执行视觉验收。

## 注册功能接入（2026-09-08）

- 入口：登录方式页与账号密码登录页的“立即注册”；注册页面提供“已有账户？去登录”。注册是独立认证路由，不改变现有“开户”模块。
- 请求：匿名 `POST /api/v1/auth/register`，必填 `email`、`password`，支持可选 `displayName`；接口层同时保留文档中的可选 `phone`，当前注册页面不收集手机号。确认密码只用于客户端校验，不发送给服务端。
- 邮箱与昵称去除首尾空白；空昵称省略；密码保持原样。邮箱最多 320 字符，昵称最多 100 字符，密码 12–128 位且包含大小写字母、数字和符号。长度计算与后端保持一致，正确处理 emoji 代理对和变体选择符，输入框不会按 UTF-16 单元提前截断密码。
- **文档差异**：Swagger 仅标出密码长度；本地后台 `src/modules/auth/presentation/dto/register.dto.ts` 还使用 `IsStrongPassword`，要求 ASCII 大小写字母、数字以及指定符号。前端提示与强度校验已按后台实现补齐，中文、emoji 等不能替代所需类别。Swagger 只声明注册的 400 错误，但 `auth.service.ts` 中重复邮箱实际返回 `409 USER_ALREADY_EXISTS`。
- 成功：`201` 响应的 `data.user.id` 与 `data.tokens` 经统一验证后交给现有会话服务，进入首页；不额外调用登录接口，也不在客户端自行授予权限。
- 失败：区分重复邮箱、校验失败、429 限流和其他服务/网络故障；请求期间禁用表单并防重复提交。注册可能已在服务端完成，因此网络失败不自动重放 POST；页面离开后迟到的响应不写入会话或触发跳转。
- 回归检查：`npm run typecheck`、`npm run lint`、`npm test -- --watch=false` 通过，共 23 个测试套件、258 项测试，其中新增注册相关 66 项。`npm run bundle:android` 与 `npm run bundle:ios` 通过；首次 Android 构建受沙箱 `spawn EPERM` 限制，获准在沙箱外使用原命令后通过，未修改构建逻辑。
- 真实联调：在 Android 模拟器中使用本地开发服务创建了独立测试用户 `codex-register-20260908083120@example.invalid`；确认密码不一致时正确拦截，注册成功后进入首页，并显示需要登录的扫码授权入口。同邮箱再次注册显示已注册提示，返回账号密码登录入口可用。未触发订单、支付或外部通知。
- 视觉与交互验收：Android 模拟器检查了 375、768、1024、1280、1440、1920 逻辑宽度，覆盖中英文、空表单、禁用、焦点、校验错误、重复邮箱及成功状态。宽屏表单保持最大 480 逻辑像素；小屏内容可滚动，无横向溢出。修正 Android 软键盘遮挡：按表单实际顶部位置避让，375 宽度下键盘展开时仍可滚动到昵称、提交按钮与返回登录入口，并实际验证返回登录可点击。验收后恢复原始 1080×2400 / 420 dpi，停在中文注册页；临时测试凭据文件已删除，截图保存在忽略目录 `artifacts/registration-qa/`。
- 会话继续沿用现有内存存储，重启 App 后需重新登录。iOS 此次仅验证 JS Bundle 构建，尚未执行 Xcode 或 iOS 真机验收。
