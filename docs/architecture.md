# 架构约束

## 三种差异边界

1. **配置**：视觉、文案、URL、功能开关、合规和渠道都属于数据，不得产生品牌分支。
2. **策略/适配器**：步骤不同但目标相同的流程使用策略；外部协议不同但领域语义相同的集成使用适配器。
3. **插件**：生命周期、数据模型或发布节奏完全独立的业务使用插件。插件可以依赖公共底座，公共底座不能依赖插件。

代码评审应阻止以下模式进入 `src/core`、`src/app` 和公共领域模块：

```ts
if (brand.id === 'some-brand') {
  // 品牌特例
}
```

## 模块协议

模块只通过 `RegisteredModule` 贡献能力：

- `routes`：页面和鉴权/功能要求；
- `menus`：菜单候选项；
- `home`：首页候选卡片；
- `translations`：领域文案；
- `initialize/dispose`：成对生命周期。

注册器拒绝重复模块和模块内重复路由。应用装配器只消费协议，不引用任一具体领域模块。

## 门控语义

功能可见必须同时满足：

```text
模块已在品牌构建清单
AND 品牌功能开关为 true
AND 服务端开关不为 false
AND 已满足登录要求
AND 用户拥有全部权限
```

敏感操作还必须由服务端再次鉴权；客户端权限只控制体验，不能作为安全边界。

## 生产替换点

示例实现保持可运行和易测试，正式业务应在接口后替换：

- `InMemorySessionStore` → Keychain/Android Keystore 支持的安全存储；
- `MemoryCache` → 带加密和版本迁移的持久缓存；
- `ConsoleLogger`/`HttpAnalyticsTransport`/`AppMonitor` → 企业采集 SDK 或自有网关，并保持事件协议与脱敏；
- 埋点内存队列 → 需要跨进程离线可靠性时替换为带加密、容量限制和版本迁移的持久队列；
- 默认运行期权限 → 登录接口返回的 entitlement；
- 示例页面 → 各领域容器、状态管理和 API repository。
